# Repository Guidelines

## Project Structure & Module Organization
This repository is a theme bundle for Omarchy. It follows the latest Omarchy theme spec: required core files at the top level, plus selective overrides where the templated defaults don't satisfy the Mumyeong aesthetic.

### Required theme files (Omarchy spec)
- `colors.toml`: Master color palette consumed by Omarchy's template renderer (`accent`, `cursor`, `foreground`, `background`, `selection_*`, `color0`–`color15`).
- `btop.theme`: btop system monitor colors.
- `neovim.lua`: LazyVim colorscheme plugin spec.
- `vscode.json`: VS Code theme extension reference.
- `icons.theme`: GTK icon theme name (single line).

### Override files (template would otherwise auto-generate)
- `hyprland.conf`: Hyprland compositor border colors (active = Ghost Silver `#F4F4F5`, inactive = Glass Edge `#71717A`). Shipping this file disables Omarchy's `default/themed/hyprland.conf.tpl` render — the `$activeBorderColor` line must stay in sync with `colors.toml::accent` manually; `$inactiveBorderColor` is the mumyeong-specific addition the built-in template does not express.
- `hyprlock.conf`: Lock screen RGBA color variables.
- `ghostty.conf`: Terminal colors only — background is lifted to `#18181B` (oma1, Onyx) so the terminal floats slightly above the wallpaper. oma2 is intentionally avoided here because it's the canonical `selection_background` across the palette; reusing it as ghostty's base would make gum/helix/etc. selection highlights invisible inside ghostty. `selection-background = #71717A` (oma3) stays visible against the lifted base. Font/window/keybind preferences stay in `~/.config/ghostty/config`; Ghostty's cascade merges them.
- `mako.ini`: Notification colors only; layout (radius, padding, icons) is inherited from `~/.local/share/omarchy/default/mako/core.ini`. Do not re-introduce an `include` of `~/.local/state/omarchy/toggles/mako.ini` — Omarchy master does not create that file and mako treats a missing include as a fatal parse error.
- `waybar.css`, `walker.css`, `swayosd.css`: Heavier UI overrides for the glassmorphism aesthetic (full `oma0`–`oma15` palette + custom shadow/blur/border rules).

### Assets & docs
- `backgrounds/`: Numbered wallpaper images (`1-bg.jpeg`, etc.).
- `preview.jpg`: Theme preview image shown in the Omarchy theme switcher.
- `colors.md`: Korean-language design notes for the palette.

### Files intentionally NOT in this theme
- `alacritty.toml`, `foot.ini`, `kitty.conf`, `chromium.theme`, `helix.toml`: Auto-generated by Omarchy's template renderer from `colors.toml`. Personal preferences (fonts, etc.) belong in `~/.config/<app>/`, not the theme.
- `hyprland.conf` with decoration/animations/window rules: Those are user desktop preferences, not theme content. Keep them in `~/.config/hypr/looknfeel.lua` and `~/.config/hypr/windows.lua` (or similar).

## Build, Test, and Development Commands
No build system or test runner.
- Activate locally: `omarchy theme set "Mumyeong"` after symlinking or copying this directory to `~/.config/omarchy/themes/mumyeong/`.
- Iterate: edit files and let `omarchy-theme-set` re-stage and reload affected components (waybar, mako, hyprctl, etc.).
- For visual changes, update `preview.jpg` so the theme switcher reflects them.

## Coding Style & Naming Conventions
- Preserve the `oma0`–`oma15` palette naming (e.g., `@define-color oma0`, `$activeBorderColor = rgb(F4F4F5)`).
- Use 2-space indentation in CSS blocks. Hyprlock variables stay at column 0.
- Hyprland: when `hyprland.conf.tpl` upstream changes, mirror the new directives into `hyprland.conf` here — shipping the file disables the built-in template, so additions don't trickle down automatically.
- New color roles (e.g., `@define-color warning`, `$check_color`) should derive from existing `oma*` values for consistency.

## Testing Guidelines
- No automated tests. Validate by activating the theme and visually checking contrast, transparency, and glassmorphism intent on representative wallpapers.
- Required visual checks after a change: Hyprland border on focus change, hyprlock unlock screen, Waybar workspace pills, Walker selected item glow, Mako notification with `urgency=high`.

## Commit & Pull Request Guidelines
- Commit messages follow `type: summary` (e.g., `feat: add hyprlock.conf`, `fix: waybar tray border`).
- One change per commit; keep summaries short and intent-focused.
- PRs should include: a brief summary, files/areas touched, and an updated `preview.jpg` for visual changes.

## Omarchy Theme System Reference

### Activation flow
`omarchy theme set "<Name>"` performs:
1. Stage a clean directory at `~/.config/omarchy/current/next-theme/`.
2. Copy the official theme files first, then user overrides from `~/.config/omarchy/themes/<name>/` (user files win field-by-field).
3. Run the template renderer over `$OMARCHY_PATH/default/themed/*.tpl` into `next-theme/`, but **skip any file already present** — that's how this theme's hand-written overrides beat the generated defaults.
4. Atomically swap `current/theme/` ← `next-theme/` and write `current/theme.name`.
5. Restart waybar, swayosd, terminal, mako, btop; then run app-specific setters (foot, gnome, browser, vscode, obsidian, keyboard).

### Template variables (from `colors.toml`)
The renderer substitutes `{{ key }}` with the literal value, plus two derived forms:
- `{{ key_strip }}` — value with the leading `#` removed (e.g., `"rgb({{ accent_strip }})"`).
- `{{ key_rgb }}` — hex converted to decimal `R,G,B`, only for `background`, `foreground`, `accent`.

Available keys: `accent`, `cursor`, `foreground`, `background`, `selection_foreground`, `selection_background`, `color0`–`color15`. See `$OMARCHY_PATH/default/themed/*.tpl` for which template uses which.

### Version compatibility notes
- **Reference repo vs installed**: `~/References/omarchy/` is the upstream dev tree and can be ahead of `~/.local/share/omarchy/`, which is what actually loads theme files at runtime. Verify migrations against the installed version, not just the reference.
- **Hyprland .conf vs .lua**: Omarchy ≤ 3.8 ships `default/themed/hyprland.conf.tpl` and sources `~/.config/omarchy/current/theme/hyprland.conf`. The post-3.8 dev tree replaces both with the `.lua` equivalents (`require("omarchy.current.theme.hyprland")`). This theme carries both files until the `.lua` loader lands in a release.

### Common gotchas
- **Toggle state files**: `~/.local/state/omarchy/toggles/{mako.ini,walker.css,hyprlock.conf}` must exist (empty is fine) — Mako/Walker theme files `include` them and fail to parse otherwise. Migration `1778405462.sh` creates them on fresh installs; older machines may need `touch`.
- **Symlinks vs copies for user themes**: Omarchy reads `~/.config/omarchy/themes/<name>/` whether it's a real directory or a symlink. Side-by-side testing works by symlinking the dev directory under a different name (e.g., `<name>-next`).

## Agent-Specific Instructions
- Keep palette semantics consistent across all override files; do not introduce hard-coded hex outside the documented `oma*` mapping.
- Do not bundle desktop preferences (window rules, animations, font choices) into theme files — they belong in the user's personal `~/.config/`.
- When the latest Omarchy theme spec changes (new required file, renamed format), update both this guide and `colors.md` along with the affected files.
